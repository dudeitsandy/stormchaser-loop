## Overview

The Disaster Entity Framework is the shared base every disaster plugs into. It gives the rest of the
game one way to ask "what disasters exist, and what do they do here?" without knowing which kind they
are. A disaster is a `DisasterEntity` that registers itself in a live list, reads its numbers from a
`DisasterData` asset, and answers three questions about a world position: how close is too close
(`DamageRadius`), how hard does the wind push (`GetWindAt`), and how much does it lift (`GetLiftFractionAt`).
A `DisasterSpawner` creates disasters during a run from a roster whose weights slide from early-run to
late-run values.

Today the Tornado (EF0 to EF5) is the only disaster built on it. Wildfire and Hailstorm (systems-index
#14, #15) and later seasons are expected to add more, so the contract must stay disaster-agnostic.

## Detailed Design

### Core Rules

1. **Registry.** Every enabled `DisasterEntity` is in the static list `DisasterEntity.Active` (added in
   `OnEnable`, removed in `OnDisable`). Consumers iterate this list; none may call
   `FindObjectsByType` per frame. The list is cleared on subsystem registration so it is empty after a
   domain reload or Enter Play Mode.
2. **Data.** A disaster's numbers come from a `DisasterData` asset: `ThreatClass`, `BehaviorPattern`,
   `MoveSpeed`, and the virtual `ThreatMultiplier` (default 1). `TornadoData` adds `EFRating`,
   `StrengthMultiplier` (returned as `ThreatMultiplier`) and `ConeScale`. `ThreatMultiplier` is the one
   number that drives scoring and lift; `ThreatClass` and `BehaviorPattern` are classification fields
   reserved for non-tornado disasters.
3. **Per-disaster queries** (virtual, defaults in brackets): `DamageRadius` [3 units],
   `GetWindAt(position)` [zero], `GetLiftFractionAt(position, exposure, liftCoefficient)` [zero].
   A subclass overrides only what it needs.
4. **Aggregation.** `TotalWindAt(position)` sums `GetWindAt` over all active disasters (winds add).
   `MaxLiftFractionAt(...)` returns the single strongest lift and that disaster's `ThreatMultiplier`
   as `efStrength` (lifts do not add). Both return zero when nothing is active.
5. **Contact damage** (owned by `VehicleHealth`, defined by this contract). While the vehicle is
   vulnerable and not wrecked, each frame it checks the active disasters in list order. The first one
   whose horizontal distance to the vehicle is within its `DamageRadius` ends the check for that frame.
   If the damage model accepts the hit (not invulnerable), the vehicle loses 1 health, is knocked back
   away from the disaster, and `PlayerDamaged` is raised. Vertical distance is ignored on purpose.
6. **Spawner lifecycle.** `RunManager` calls `Begin()` when the run starts and `Stop()` when it ends.
   `Stop()` ends new spawns; disasters already alive keep going. Before `Begin()` it never spawns.
7. **Spawner timing.** The first attempt is `FirstSpawnDelay` after `Begin()`. At each attempt it
   spawns one disaster if fewer than `MaxConcurrent` are alive, then schedules the next attempt
   (F3). The cap counts tornadoes only.
8. **Spawner choice.** The roster holds one entry per disaster type/level with an `EarlyWeight` and a
   `LateWeight`. The pick uses run progress from `SessionTimer` (F1), so stronger disasters become
   likelier as the run goes on. The scene roster is EF0 to EF5, with both weight columns summing to 100.
9. **Spawner placement.** A new disaster appears ahead of the player, inside an arc around the
   player's horizontal facing and between a minimum and maximum distance (F2).
10. **Photo target.** `PhotoTrigger` picks the nearest active disaster within its range by 3D
    distance; that disaster's `ThreatMultiplier` feeds the photo score (`photo-scoring.md`).

### States and Transitions

The spawner has three states. Each disaster's own lifecycle (the Tornado's forming, mature and
dissipating phases) belongs to its own system and is not defined here.

| State | Meaning | Enter when | Exit to |
|---|---|---|---|
| Idle | Never spawns (next time is infinity) | Scene load | Running on `Begin()` |
| Running | Attempts spawns on the F3 schedule | `Begin()` | Stopped on `Stop()` |
| Stopped | No new spawns; live disasters continue | `Stop()` | Running on the next `Begin()` |

## Formulas

**F1. Spawn weight and pick**

The spawn weight and pick formula is defined as:

`p = clamp01(SessionTimer.Progress)`
`w_i = max(0, early_i + (late_i − early_i) × p)`
`index = the first i where (roll × Σw) < (w_0 + … + w_i)`; `−1` if `Σw ≤ 0`.

**Variables:**
| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| p | float | 0 to 1 | `SessionTimer.Progress` | Run progress, clamped |
| early_i, late_i | float | 0 to 30 in the scene | roster (scene) | Weight at run start and run end |
| roll | float | 0 to 1 | `Random.value` | Uniform draw; see Edge Cases for the 1.0 case |
| index | int | −1 to roster size − 1 | calculated | Chosen roster entry; −1 means no spawn this attempt |

**Output Range:** one roster index or −1. Negative blended weights count as 0. Mismatched list lengths
throw `ArgumentException`.
**Example (scene roster, EF0 to EF5, early 30/30/25/12/3/0, late 5/10/20/25/25/15):** at p = 0.5 the
weights are 17.5 / 20 / 22.5 / 18.5 / 14 / 7.5 (sum 100). roll = 0.51 gives threshold 51 and cumulative
17.5, 37.5, 60, so index 2 (EF2). At p = 0 the EF5 weight is 0; at p = 1 it is 15 %.

**F2. Spawn placement**

The spawn placement formula is defined as:

`angle ~ U(−Arc, +Arc)` about the player's horizontal facing; `dist ~ U(MinDist, MaxDist)`
`pos = player + Rot(angle) × facing_xz × dist`; `pos.x, pos.z = clamp(·, −Half, +Half)`; `pos.y = 0`.

**Variables:**
| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| Arc | float (deg) | 0 to 180 | constant | 70 |
| MinDist, MaxDist | float | > 0 | constant | 45 and 70 units |
| Half | float | > 0 | constant | **85** (legacy arena); intended: the playable world extent |
| facing_xz | Vector3 | unit | player `forward` | Normalized with y removed |

**Output Range:** a point on the ground plane. With no player it uses the origin and +Z.
**Example:** player at the origin facing +Z, angle 0, dist 60 gives (0, 0, 60). Player at (80, 0, 0)
facing +X: raw x = 140 clamps to 85, so the spawn is 5 units away (see Edge Cases).

**F3. Spawn cadence**

The spawn cadence is defined as:

`t_first = t_Begin + FirstSpawnDelay`. At each due time: spawn if `alive < MaxConcurrent`, then
`t_next = now + (alive_after == 0 ? EmptySkyRetry : SpawnInterval)`.

**Variables:**
| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| FirstSpawnDelay | float (s) | ≥ 0 | constant | 1.5 |
| SpawnInterval | float (s) | > 0 | scene | **10** (code default 9) |
| EmptySkyRetry | float (s) | > 0 | constant | 2 |
| MaxConcurrent | int | ≥ 1 | constant | 3 |

**Output Range:** one spawn attempt per due time. `alive_after` is measured after the spawn call, so it
is 0 only when the attempt itself produced nothing; the retry never shortens a wait that is already
running (see Edge Cases).
**Example:** if every tornado survives, spawns land at 1.5, 11.5 and 21.5 s; the next attempt at 31.5 s
spawns only if fewer than 3 are alive.

**F4. Aggregation**

The aggregation rule is defined as:

`TotalWind(P) = Σ_e GetWindAt_e(P)`;  `Lift(P) = max_e GetLiftFractionAt_e(P)` with `efStrength = ThreatMultiplier` of that disaster
(0 and 0 if none is above 0).

**Variables:**
| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| P | Vector3 | world | caller | Query position |
| GetWindAt | Vector3 | XZ, units/s | disaster | Per-disaster wind |
| GetLiftFractionAt | float | ≥ 0 | disaster | Lift as a fraction of vehicle weight |

**Output Range:** wind is unbounded above (it adds); lift is the single strongest value.
**Example:** winds (3, 0, 0) and (−1, 0, 2) give (2, 0, 2). Lifts 0.2 (strength 1) and 0.5 (strength 2.5)
give 0.5 and efStrength 2.5.

**F5. Vortex wind (`WindField.Vortex`)**

The vortex wind formula is defined as:

`v = (−outward × inflow + tangent × swirl) × (1 − d/R)²` for `0.001 ≤ d < R`, else zero.
`outward` = unit XZ offset from the center; `tangent = up × outward` (counter-clockwise from above).

**Variables:**
| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| d | float | ≥ 0 | calculated | XZ distance from the center |
| R | float | > 0 | disaster | Wind radius |
| inflow, swirl | float (units/s) | ≥ 0 | disaster | Peak pull toward the center and sideways push |

**Output Range:** a vector on the XZ plane, largest at the center, zero at and beyond R.
**Example:** R = 20, d = 10, inflow 4, swirl 8: factor 0.25, so (inward 1, sideways 2), magnitude about
2.24 (matches the existing unit test). How the vehicle turns this into force is `vehicle-feel.md` F11.
*Tornado's instance of F5 (until a Tornado GDD exists):* `R = (14 + 10 × Cone) × Intensity`, inflow 7 and
swirl 11, both scaled by `(0.5 + 0.75 × √ThreatMultiplier) × Intensity` (EF0 1.25×, EF5 2.0×).

**F6. Contact radius (Tornado's `DamageRadius`)**

The tornado contact radius is defined as:

`DamageRadius = 0` if `Intensity < 0.4`, else `(1.2 + 1.3 × Cone) × Intensity`. Base-class default is 3.
Contact test: `dx² + dz² ≤ DamageRadius²`.

**Variables:**
| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| Intensity | float | 0 to 1 | Tornado lifecycle | Current lifecycle strength |
| Cone | float | 0.6 to 2.4 | `TornadoData.ConeScale` | Funnel size |

**Output Range:** 0 to about 4.3 units at EF5.
**Example:** EF2 (Cone 1.0) at full intensity: 2.5. EF5 (Cone 2.4): 4.32. Any tornado at Intensity 0.3: 0.

## Edge Cases

**Handled in the code**
- **Progress outside 0 to 1**: clamped before blending.
- **All weights zero**: the pick returns −1 and that attempt spawns nothing.
- **Mismatched weight lists**: throws `ArgumentException`.
- **Missing prefab or empty roster**: the attempt returns without spawning or throwing.
- **Wind at the exact center (d < 0.001) or outside R**: zero, so no divide-by-zero.
- **Disaster disabled or destroyed**: removed from `Active` in `OnDisable`.
- **Domain reload / Enter Play Mode**: the static list is cleared.
- **No player assigned**: spawns around the origin facing +Z.
- **Vehicle wrecked or not vulnerable**: contact damage is skipped.
- **Tornado below Intensity 0.4**: `DamageRadius` is 0, so a forming or dying funnel cannot hurt.

**Not handled (observed gaps)**
- ⚠️ **Empty sky waits the full interval.** `EmptySkyRetry`'s tooltip says the sky should never stay empty
  long, but the retry only applies when a spawn attempt produced nothing. After the last tornado dies the
  next attempt can be up to `SpawnInterval` (10 s) away.
- ⚠️ **Spawns near the bounds can land on the player.** Clamping to `±Half` can pull a spawn well inside
  `MinDist`, even to a few units away (F2 example).
- ⚠️ **Spawn height is fixed at 0.** The streamed world has terrain height (ADR-0004), so a ground-level
  y of 0 may sit under or above the surface.
- ⚠️ **`Random.value` can return exactly 1.0.** Unity documents it as inclusive of 1.0, but
  `SpawnTable.Pick` documents `roll01` as `[0,1)`. At roll = 1.0 no entry matches and it returns the last
  index even if that entry's weight is 0 (an EF5 at run start). Very rare, but not impossible.
- ⚠️ **Only the first in-range disaster is considered per frame**, in enable order; a second disaster
  also in range does not contribute and is not checked.
- ⚠️ **Phase Arc and Interaction Tags** (vision-1.0) are not in the base class.

**Unclear (need a decision)**
- ❓ **Lift takes the max while wind sums.** Two overlapping funnels add their wind but not their lift. Intended?
- ❓ **`MaxConcurrent` with several disaster types.** Is the cap total, or per type? Today it counts tornadoes only.
